# Instruction files and a documentation map for AI coding agents (CLAUDE.md, AGENTS.md, path-scoped rules, skills)

Research date: 2026-11-23. Evidence labels: [VENDOR] official docs or vendor blog; [MEASURED] controlled or large-scale empirical study; [ANECDOTE] practitioner opinion; [SNIPPET] seen only in search-result text, not read in full. Unless marked [SNIPPET], a page was fetched, but the fetch tool returns a model-generated extract, not verbatim page text. Quotes below are as returned by that extract. Where a page was too long for one fetch, I say which part was read.

## (a) What belongs in the always-loaded file vs. on-demand documents

### Takeaway
All three vendors converge on: keep the always-loaded file short and limited to things the agent cannot infer from the code (commands, non-obvious conventions, hard boundaries). Put topic- or path-specific material in files that load on demand. Anthropic gives a concrete target (under 200 lines per CLAUDE.md). OpenAI says its own AGENTS.md is a roughly 100-line table of contents. GitHub gives almost no size guidance. Anything that must hold with zero exceptions belongs in a hook, not in prose.

### Cited Findings
- Anthropic [VENDOR]: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence. Move instructions that matter for only part of the codebase into path-scoped rules, which load only when Claude works with matching files." Imports "help you organize a long file but don't reduce its context cost, because imported files load together with the CLAUDE.md that imports them." — [Claude Code memory docs](https://code.claude.com/docs/en/memory) (read about 54KB, partially via grep of the saved page; undated, living doc, current as of Nov 2026, references Claude Code v2.1.277+)
- Anthropic: contradictory instructions: "Claude may pick one arbitrarily"; review root, nested and `.claude/rules/` files periodically. `/doctor prompt-audit` finds instructions written for older models, references to files or commands that don't exist, and contradicting files; it only proposes edits. — [memory docs](https://code.claude.com/docs/en/memory)
- Anthropic: block-level HTML comments in CLAUDE.md are stripped before injection, so maintainer notes cost no tokens. Imports are recursive to a maximum depth of four hops. Subdirectory CLAUDE.md files load on demand; ancestors load at launch. — [memory docs](https://code.claude.com/docs/en/memory)
- Anthropic: auto memory loads "up to the first 200 lines or 25KB of MEMORY.md". — [memory docs](https://code.claude.com/docs/en/memory)
- Anthropic best practices [VENDOR]: `CLAUDE.md` is for guidelines and "Claude is allowed to decide a guideline doesn't apply". If something must happen every time, use a hook, deny rule or managed setting. "If you keep adding emphasis to a CLAUDE.md line and Claude still misses it, that's a sign the line belongs in a hook." If Claude keeps ignoring a line, "either the file has grown long enough that the line gets lost, or the line is a rule that can't have exceptions". The typecheck line should be only the command, and enforcement belongs in a `Stop` hook. Also: keep the enforced set small ("If you ever find yourself at forty of them, most are probably preferences"). — [Best practices](https://code.claude.com/docs/en/best-practices) (about 51KB, read via grep of key passages)
- Anthropic: team procedures go in skills. A skill's name and description sit in context every session, but the full file loads only when the task calls for it. "The CLAUDE.md rule applies to skills too: only write down what Claude can't find on its own." — [Best practices](https://code.claude.com/docs/en/best-practices)
- Anthropic skills [VENDOR]: "Keep SKILL.md under 500 lines"; move reference material to separate files linked from SKILL.md. Combined `description` + `when_to_use` is truncated at 1,536 characters in the skill listing. The listing "adds to your context on every turn". After auto-compaction, each invoked skill keeps its first 5,000 tokens, with a shared 25,000-token budget. `disable-model-invocation: true` removes the description from context, so the skill runs only on `/name`. Skills also accept a `paths` glob. — [Skills docs](https://code.claude.com/docs/en/skills) (first 100,000 of about 120,000 chars read)
- Anthropic [VENDOR]: for large repos, per-directory CLAUDE.md files so "Claude loads repository-wide rules plus only the conventions for the code you're working in". Choose per-directory CLAUDE.md when directory owners keep conventions beside the code. Choose `.claude/rules/` with `paths:` when you want everything in one central place or one rule spans scattered paths. Keep files current by reviewing CLAUDE.md edits in PRs and by revisiting them after major model releases, because "instructions that worked around an older model's limitation may become overhead". `claudeMdExcludes` skips irrelevant files. Subdirectory skills accumulate: "names always load" but "some skills lose their descriptions entirely" when there are many. — [Large codebases guide](https://code.claude.com/docs/en/large-codebases) (read in full)
- Anthropic: path-scoped rules (`paths:` frontmatter in `.claude/rules/*.md`) load when Claude reads, writes or edits a matching file, and also on single-file `cat`/`head` via Bash. `.claude/rules/` supports symlinks. — [memory docs](https://code.claude.com/docs/en/memory)
- OpenAI [VENDOR], "harness engineering" article: "A short AGENTS.md (roughly 100 lines)" injected into context that works as a map. "Treat AGENTS.md as the table of contents." Knowledge base lives in a structured `docs/` directory as "the system of record", holding design docs, execution plans, product specs, references and quality grades. Agents "start with a small, stable entry point and are taught where to look next". Lesson: "give Codex a map, not a 1,000-page instruction manual". — [OpenAI, Harness engineering](https://openai.com/index/harness-engineering/) (fetched extract; I could not confirm the publication date from the extract. Verify before citing a date.)
- OpenAI, same article: a recurring "doc-gardening" agent scans for stale docs and opens fix-up PRs. Linters and CI jobs validate that the knowledge base is "up to date, cross-linked, and structured correctly". — [OpenAI, Harness engineering](https://openai.com/index/harness-engineering/)
- OpenAI Codex docs [VENDOR]: default size cap `project_doc_max_bytes` = 32 KiB combined. Codex stops adding files once the cap is reached. Discovery walks from the project root down to the cwd, one file per directory (`AGENTS.override.md`, then `AGENTS.md`, then `project_doc_fallback_filenames`), concatenated root-down. Files nearer the cwd override earlier guidance. — [Codex AGENTS.md guide](https://learn.chatgpt.com/docs/agent-configuration/agents-md) (the old URL developers.openai.com/codex/guides/agents-md returns a 308 redirect to this page)
- GitHub Copilot docs [VENDOR]: supports `.github/copilot-instructions.md` (repo-wide), `.github/instructions/*.instructions.md` with `applyTo` globs (path-specific; per the page, GitHub.com support is for the cloud agent and code review), `AGENTS.md` anywhere in the repo ("nearest one in the directory tree takes precedence"), or a single `CLAUDE.md` or `GEMINI.md` at the root. All relevant sets are provided to Copilot, so "avoid conflicting instructions". The only length guidance is a sample prompt: "Instructions must be no longer than 2 pages". The page does not mention a 4,000-character or 1,000-line limit, so I could not confirm the figure sometimes quoted for code review. — [GitHub Docs: repository custom instructions](https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-instructions)
- GitHub blog [VENDOR], 2025-11-19 (updated 2025-11-25), lessons from 2,500+ repos: top files cover "commands, testing, project structure, code style, git workflow, and boundaries". Put executable commands (with flags) early. "One real code snippet showing your style beats three paragraphs describing it." Three-tier boundaries (always / ask first / never). Vague personas fail. "The best agent files grow through iteration, not upfront planning." — [GitHub blog](https://github.blog/ai-and-ml/github-copilot/how-to-write-a-great-agents-md-lessons-from-over-2500-repositories/)
- agents.md site [VENDOR/community standard]: plain Markdown, no required fields, no size guidance. Nested AGENTS.md for monorepos, the nearest file wins, and an explicit chat prompt overrides everything. States "over 60k open-source projects" use it and notes the main OpenAI repo had 88 AGENTS.md files. — [agents.md](https://agents.md)
- HumanLayer [ANECDOTE], 2025-11-25: "Frontier thinking LLMs can follow ~150-200 instructions with reasonable consistency", Claude Code's system prompt has "~50 individual instructions", "general consensus is that < 300 lines is best", and the author's root file is under 60 lines. Claims Claude Code wraps CLAUDE.md in a reminder that it need not respond unless "highly relevant", so non-universal content is more likely to be ignored. "Never send an LLM to do a linter's job." Advises against `/init` and auto-generation. The 150-200 figure is the author's estimate, not a measured result from this post. — [HumanLayer](https://www.humanlayer.dev/blog/writing-a-good-claude-md)
- Vercel [VENDOR with commercial interest, author-built evals], 2026-01-27: on Next.js 16 APIs absent from training data, baseline 53%, skill (default) 53%, skill with explicit instructions 79%, AGENTS.md docs index 100%. "In 56% of eval cases, the skill was never invoked." The index was compressed from about 40KB to 8KB with the same pass rate. The article doesn't report the number of runs. Skills are suggested for vertical, user-triggered workflows. The authors say the gap may close as models improve. — [Vercel blog](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)

### Inferences
- A proportionate target for a solo Claude Code project: root file well under Anthropic's 200 lines (OpenAI's own example is about 100). Contents: build/test/lint commands, non-obvious conventions, hard "never" boundaries, and a pointer table to docs. Everything else lives in on-demand docs.
- The Vercel result and Anthropic's skills docs are in tension. Skills save context but may not be invoked (56% non-invocation in one vendor eval). The practical reconciliation is that critical knowledge goes in the always-loaded index or an explicit pointer, and skills are for explicit procedures the user triggers.
- Imports organize but do not save context. So `@file` is the wrong tool for "load on demand"; plain-path pointers or path-scoped rules are.

### Gaps
- No official numeric limit for Copilot instruction files beyond the "2 pages" prompt sample. I did not find a primary source for the 4,000-character code-review limit.
- The OpenAI harness-engineering article's date was not confirmed.
- I could not verify HumanLayer's 150-200 instruction figure against its underlying paper.

## (b) Structuring a doc map so the agent reads the right document at the right time

### Takeaway
The converging pattern is a small always-loaded entry point that works as an index. Vendors favor a map or table of contents (OpenAI), self-descriptively named files (HumanLayer), and mechanical scoping by path (Claude rules, Copilot `applyTo`, nested AGENTS.md). Trigger-oriented ("when doing X, read Y") phrasing is consistent with this guidance but I found no controlled comparison of list-of-files versus situation-based maps.

### Cited Findings
- OpenAI: entry point plus `docs/` as system of record, with progressive disclosure ("taught where to look next"); mechanical validation that the knowledge base is cross-linked and structured correctly. — [OpenAI, Harness engineering](https://openai.com/index/harness-engineering/)
- Vercel's working index design: a compact pipe-delimited index (root path, one line per directory listing its files) that instructs the agent to prefer retrieval over pre-training knowledge, and tells it which file to read when needed. 8KB held 100% on their eval. — [Vercel blog](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)
- HumanLayer: keep task-specific instructions "in separate markdown files with self-descriptive names" that the root file lists, so the agent reads only what is relevant. — [HumanLayer](https://www.humanlayer.dev/blog/writing-a-good-claude-md)
- Anthropic: three scoping mechanisms (nested CLAUDE.md, `.claude/rules/` with `paths:`, skills with `paths` or description-based triggering). Pointer-style routing is cheapest in always-loaded context when it uses plain paths rather than `@` imports. — [Large codebases guide](https://code.claude.com/docs/en/large-codebases), [memory docs](https://code.claude.com/docs/en/memory)
- Skills use progressive disclosure natively: SKILL.md as overview and navigation, with `reference.md`, `examples.md` and scripts loaded on demand. — [Skills docs](https://code.claude.com/docs/en/skills)
- ETH Zurich study: codebase overviews in context files "did not help agents find relevant files sooner". So an index is useful for routing to non-obvious documents, not as a replacement for the agent's own exploration. — [arXiv 2602.11988 (HTML)](https://arxiv.org/html/2602.11988v1)
- Agent READMEs analysis of 2,303 files: structure is shallow (one H1, content under H2/H3), and "no established structure" exists. — [arXiv 2511.12884](https://arxiv.org/html/2511.12884v1), [SNIPPET for the no-structure remark: arXiv 2510.21413](https://arxiv.org/html/2510.21413v4)

### Inferences
- For a solo owner a flat table "situation / trigger -> document path -> one-line why" is probably enough, and it is the form that fits both OpenAI's "map" and Vercel's compact index. Splitting into nested CLAUDE.md files or path-scoped rules pays off only when areas of the repo have distinct conventions. A single-person repo can usually defer that.
- Because overviews don't speed file discovery (ETH), the map should list only documents the agent cannot find by search: decisions, invariants, workflows, gotchas.
- Docs the agent must read before touching a given area are good candidates for `paths:` rules, since loading is automatic rather than depending on the agent choosing to follow a pointer.

### Gaps
- I did not retrieve real public repositories' instruction files. My attempt to read `openai/codex` AGENTS.md via raw URL returned 404 and the `gh` API calls were blocked (repository not attached). So I have no verified concrete example of a "when doing X, read Y" map from a named public repo. The report writer should treat this as unsupported rather than infer one. Candidate repos to inspect later: `openai/codex`, `vercel/next.js` (the agents.md site and OpenAI cite heavy AGENTS.md use; I did not verify their content).
- No controlled study compares file-listing against situation/trigger-based indexes.

## (c) Empirical evidence on whether these files help or hurt

### Takeaway
Measured evidence is mixed and leans cautious: LLM-generated context files slightly hurt and cost about 20% more; developer-written files help by about 4% on average and mainly where they state non-obvious, repo-specific tooling. A separate factorial study found file length and contradictions did not measurably change adherence in its setting. Vercel's eval (vendor-built) shows large gains for docs the model doesn't know.

### Cited Findings
- ETH Zurich / Gloaguen et al., "Evaluating AGENTS.md", arXiv 2602.11988, submitted 2026-02-12 [MEASURED]; ICLR 2026 workshop listing. Results: LLM-generated files lowered resolution about 0.5% on SWE-bench Lite and 2% on AGENTbench (drops in 5 of 8 settings). Developer-written files improved resolution about 4% on average (not for Claude Code). Cost rose about 20% (SWE-bench Lite) and 23% (AGENTbench), roughly 2.5 to 3.9 extra steps. Agents obey instructions: `uv` used about 1.6 times per instance when mentioned vs under 0.01 when not. When existing docs were removed, LLM-generated files improved results about 2.7%, i.e. much of their content duplicates existing docs. Recommendation: omit LLM-generated files and include only minimal human-written requirements such as repo-specific tooling. Limits: Python only, AGENTbench is 138 instances from 12 repos, only task resolution measured (no efficiency or security). — [arXiv abstract](https://arxiv.org/abs/2602.11988), [HTML full text extract](https://arxiv.org/html/2602.11988v1). A search tool noted that the PDF and venue listings word the headline differently (softer "no significant improvement" vs stronger "reduce success"); I did not resolve which wording matches the latest version.
- McMillan, "Instruction Adherence in Coding Agent Configuration Files: A Factorial Study of Four File-Structure Variables", arXiv 2605.10039, submitted 2026-05-11, single author, abstract read [MEASURED]: 1,650 Claude Code CLI sessions on two TypeScript codebases, mostly Sonnet 4.6. File size, instruction position, file architecture and contradictions in adjacent files each showed no detectable effect on adherence. The size and contradiction nulls have Bayes-factor support (BF10 0.05-0.10); the structure and position nulls are weaker. Largest effect: each additional function generated in a session is associated with about 5.6% lower odds of compliance (OR 0.944), found post hoc but replicated. Compliance depended more on task and session progress. Caution: this challenges "long files get ignored", but covers one agent, two codebases, and the file sizes tested. — [arXiv 2605.10039](https://arxiv.org/abs/2605.10039)
- Agent READMEs, arXiv 2511.12884 (2025-11), 2,303 context files from 1,925 repos (922 Claude Code, 694 Codex, 687 Copilot) [MEASURED, descriptive]: median length about 485 words (Claude Code), 335.5 (Codex), 535 (Copilot); readability "very difficult"; 59-67% of files modified in multiple commits, with small additions and few deletions; among 332 labeled Claude Code files, Testing 75.0%, Implementation details 69.9%, Architecture 67.7%, Build/run 62.3%, but Security and Performance each 14.5% and UI/UX 8.7%. Only the first 100,000 of about 135,000 chars were read. — [arXiv 2511.12884](https://arxiv.org/html/2511.12884v1). It describes what files contain; it doesn't measure outcomes.
- Related large-scale descriptive work [SNIPPET only]: 10,000-repo preliminary study with no established structure and varied instruction style — [arXiv 2510.21413](https://arxiv.org/html/2510.21413v4); 2,926 repos, eight configuration mechanisms, context files dominant — [arXiv 2602.14690](https://arxiv.org/html/2602.14690v1). Not read.
- Another context-file ablation exists [SNIPPET only]: "Do Context Files Help Coding Agents? A Two-Agent Ablation Study on Real Repositories", arXiv 2607.27250 (author Prakhar Khatri, PDF metadata dated 2026-07-31). The PDF was unreadable by the fetch tool, so I have no findings. — [arXiv 2607.27250](https://arxiv.org/pdf/2607.27250)
- Vercel eval [VENDOR, author-built, sample size not reported]: see section (a). Gains are specific to knowledge missing from training data. — [Vercel blog](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)
- GitHub blog [VENDOR, observational over 2,500 repos, method not detailed in the extract]: specificity, commands, examples and boundaries distinguish good files. — [GitHub blog](https://github.blog/ai-and-ml/github-copilot/how-to-write-a-great-agents-md-lessons-from-over-2500-repositories/)

### Inferences
- Reading ETH and McMillan together: agents do follow what is written (ETH), so the risk is wrong, redundant or unnecessary content (extra steps, extra cost), not mere length. McMillan's null on size suggests the "ignored as files grow" claim is not yet supported by controlled evidence, at least for adherence in Claude Code on TypeScript. It conflicts with Anthropic's own wording ("longer files ... reduce adherence"), which is vendor guidance without a published measurement in what I read.
- For a solo repo: write the file by hand, put in what the agent cannot discover (non-standard tooling, gotchas, constraints), and skip generated overviews.
- Both academic studies are on narrow samples (Python benchmark; two TypeScript repos), and the field moves fast. Sonnet 4.6 and GPT-5.x era models may differ from late-2026 models.

### Gaps
- No evidence found measuring the benefit of a situation-keyed doc map specifically.
- The 2607.27250 paper's findings are unread.
- ETH numbers are from a fetch extract of the HTML; the abstract page itself gave no percentages.

## (d) Failure modes and reported fixes

### Takeaway
Reported failures: bloat from accumulation, stale or wrong instructions followed with full confidence, contradictions across files, wholesale imported or LLM-generated instruction sets, and rules that need enforcement but are written as prose. Fixes: prune, convert to hooks/CI, review against each new model, mechanically validate docs, hand-write.

### Cited Findings
- Thoughtworks Technology Radar, "Agent instruction bloat", Vol. 35 (Nov 2026; updated 2026-11-04; first published 2026-04-15), ring "Caution" [practitioner/analyst opinion, cites research without new measurement]: instructions "grow over time", become "long, contradictory, and stale", worse with wholesale-imported external sets; models attend less to mid-context content; hand-written beats LLM-generated. Remedies: turn instructions into deterministic hooks or checks, re-evaluate and delete instructions against each new model ("progression testing"), progressive disclosure, add deliberately and selectively. Notes Anthropic removed over 80% of Claude Code's system prompt for its latest models with no measurable loss (as relayed by the entry; not verified against an Anthropic source). — [Thoughtworks Radar](https://www.thoughtworks.com/en-sg/radar/techniques/agent-instruction-bloat)
- OpenAI harness-engineering article: the big-file failures were (1) context is scarce, (2) "when everything is important, nothing is", (3) "it rots instantly", (4) hard to verify mechanically. Fix: short map, structured `docs/`, doc-gardening agent, linters and CI. — [OpenAI](https://openai.com/index/harness-engineering/)
- Anthropic: contradictions resolved arbitrarily; emphasis (IMPORTANT) won't rescue a line lost in a long file; zero-exception rules belong in hooks; revisit instructions after model releases; `/doctor prompt-audit`. — [memory docs](https://code.claude.com/docs/en/memory), [best practices](https://code.claude.com/docs/en/best-practices), [large codebases](https://code.claude.com/docs/en/large-codebases)
- ETH study: LLM-generated files cost more and slightly reduce success; much of their content duplicates existing docs. — [arXiv 2602.11988](https://arxiv.org/html/2602.11988v1)
- Counter-evidence: McMillan found no detectable effect of size, position, architecture or contradictions on adherence in its setup. — [arXiv 2605.10039](https://arxiv.org/abs/2605.10039)
- Stale-docs argument "a stale AGENTS.md gets obeyed with full confidence" [ANECDOTE, SNIPPET] — [DEV Community](https://dev.to/wolfejam/your-agentsmd-is-already-stale-and-your-agent-trusts-it-completely-2nfh). Reasonable, consistent with ETH's "agents follow instructions", but not itself measured.
- Skills not invoked: 56% of cases in Vercel's eval; wording of the trigger swung results widely. — [Vercel blog](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)
- Skill listing overflow: with many skills "some skills lose their descriptions entirely". — [Large codebases guide](https://code.claude.com/docs/en/large-codebases)
- Agent READMEs: maintenance is additive, with few deletions, which is the mechanism for bloat. Security and performance guidance is rare. — [arXiv 2511.12884](https://arxiv.org/html/2511.12884v1)

### Inferences
- A solo owner has no reviewer, so the cheap defenses are: delete-more-than-add habit, a pre-release or per-model-upgrade prune pass, `/doctor prompt-audit`, and hooks for the few hard rules. A CI-based docs linter or doc-gardening agent as in OpenAI's setup is likely over-engineering for one person, but a small script that checks that every path in the map exists is cheap and proportionate.
- Disagreement to flag: vendors (Anthropic, Thoughtworks, HumanLayer) assert long files reduce adherence; the one controlled adherence study I found shows no size effect. Ensure the final report presents this as unresolved.

### Gaps
- No quantified data on how often instruction files go stale in practice.
- Few primary-source failure reports; most are blog-level.

## (e) AGENTS.md as canonical file with CLAUDE.md importing it (cross-tool setup, as of Nov 2026)

### Takeaway
Workable and now officially supported by Anthropic. Recommended form: CLAUDE.md containing `@AGENTS.md` plus any Claude-specific lines. Copilot and Codex both read AGENTS.md natively. Caveats are about symlinks, precedence rules, feature differences and the version floor.

### Cited Findings
- Claude Code [VENDOR]: can read `AGENTS.md` natively (requires v2.1.277 or later); default `claude-md-or-agents-md` reads AGENTS.md only when there is no CLAUDE.md or CLAUDE.local.md in the working directory or above. If both exist, only CLAUDE.md files load unless the `claude-md-and-agents-md` setting is chosen. For a shared file, put `@AGENTS.md` in a CLAUDE.md and add Claude-specific content below. Claude Code skips an AGENTS.md it has already loaded, so an imported file isn't read twice. — [memory docs](https://code.claude.com/docs/en/memory)
- Caveats from the same docs: adding a `CLAUDE.local.md` stops Claude from reading AGENTS.md by default; some sessions (before v2.1.281, e.g. Bedrock or telemetry disabled) could read CLAUDE.md only, so the import remains the safe route; `InstructionsLoaded` hooks don't fire for AGENTS.md read through the setting (they do fire when imported or symlinked from CLAUDE.md); `--add-dir` directories' AGENTS.md don't load. A `SessionStart` hook that prints AGENTS.md should be removed since it duplicates content. — [memory docs](https://code.claude.com/docs/en/memory)
- Symlink option (`ln -s AGENTS.md CLAUDE.md`): Claude's Edit and Write tools refuse to write through a symlink and tell Claude to edit the target instead. Windows symlinks need privileges. — [memory docs](https://code.claude.com/docs/en/memory); [SNIPPET: GitHub issue anthropics/claude-code #66559](https://github.com/anthropics/claude-code/issues/66559); [SNIPPET: DEV Community](https://dev.to/yurukusa/keep-agentsmd-and-claudemd-in-sync-5-user-side-fixes-and-where-each-quietly-breaks-35p5)
- Codex [VENDOR]: reads AGENTS.md natively; has `project_doc_fallback_filenames` for alternate names; 32 KiB combined cap. — [Codex guide](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- GitHub Copilot [VENDOR]: reads AGENTS.md (nearest wins), and also a root CLAUDE.md or GEMINI.md; path-specific `.github/instructions/*.instructions.md` is a Copilot-specific mechanism that other tools do not read; code review reads instructions from the head branch. — [GitHub Docs](https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-instructions)
- agents.md lists Codex, Gemini CLI, Cursor, Copilot coding agent, Windsurf, Zed, Aider, Devin, Jules and others as supporters, and says it does not mention CLAUDE.md. The listing was read from the live site. — [agents.md](https://agents.md)
- Drift when two files are maintained separately is the main practitioner complaint [ANECDOTE, SNIPPET] — [DEV Community](https://dev.to/hassekf/claudemd-and-agentsmd-in-the-same-project-how-to-avoid-maintaining-two-files-4k9)

### Inferences
- Single-source rule: keep all shared content in AGENTS.md, keep CLAUDE.md as a two-line wrapper (`@AGENTS.md` plus Claude-only notes). For a solo Claude-first project this is cheap insurance, and with no other tool in use it can be skipped until needed. If Claude Code is the only agent, a plain CLAUDE.md is equally valid.
- Claude-specific mechanisms (`.claude/rules` `paths:`, skills, hooks) have no AGENTS.md equivalent. Content that depends on them will not reach Copilot or Codex, so keep the always-loaded shared file self-sufficient and treat path-scoped rules as a Claude-only optimization.
- Precedence and path-scoping differ per tool (Copilot nearest-wins; Codex root-down concatenation with nearer overriding; Claude concatenates ancestors and loads subdirectory files on demand), so contradictions between root and nested files may resolve differently across tools.

### Gaps
- No official statement from Anthropic, OpenAI or GitHub about guaranteed long-term interoperability. Claims here are from current docs only.
- I did not test the three tools myself.

## Proportionality notes for a solo owner (synthesis of the above, marked as inference)
- Proportionate: a hand-written root file under about 100 to 200 lines; a short situation-to-document map; hooks for 1 to 3 truly hard rules; a prune pass when upgrading models; running `/doctor prompt-audit` occasionally.
- Probably disproportionate: nested CLAUDE.md per directory, many path-scoped rules, doc-gardening agents, CI doc linters, cross-tool sync tooling (unless you really use several tools).
- Avoid: LLM-generated overviews, repeating what the code or existing docs already say, emphasis markers as a substitute for hooks.
