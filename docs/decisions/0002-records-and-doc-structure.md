# 0002 记录方式：短规则文件、覆盖式状态文件、少量决策记录

- 状态：提议中
- 日期：2026-11-23

## 背景

每次会话都从空白上下文开始，长对话还会被压缩，所以项目状态必须存在仓库里。但 AI 容易不断新建文档，时间长了没人看，过时的内容还会误导后面的工作。

## 选项

1. 采用现成的规格驱动流程：每个功能生成一套需求、设计、任务文档。
2. 自己定一个小的固定结构：规则文件、状态文件、任务清单、决策记录、调研、学习笔记。
3. 不定结构，需要什么写什么。

## 决定

选 2。结构见 `AGENTS.md` 的文档地图。规则写在 `AGENTS.md`（各家 AI 工具通用），`CLAUDE.md` 引用它并补充 Claude Code 专用的内容。

## 理由

- 选项 1 被独立评测批评为冗长、容易造成文档泛滥，对一人项目过重。
- 选项 3 正是要避免的情况。
- 规则文件要手写、要短。实测显示 AI 自动生成的规则文件让完成率略降、成本升约 20%，只写 AI 猜不到的内容才有帮助。
- 状态文件整份重写而不追加，避免变成没人读的流水账。
- 用 `AGENTS.md` 是为了以后让其他厂商的模型审查时能读到同一份规则。

## 代价和防范

- "教训必须变成检查或规则"和"不在地图之外新建文档"这两条没有找到正反证据，是推断。用一段时间后回头看是否有效。
- 目前这些规则只是文字。第一批代码加入时，把能自动判断的部分做成自动检查，包括检查文档地图里的路径是否存在。
- 规则文件会自然变长。每个里程碑结束时修剪一次。

## 依据

`docs/research/reports/AI 协作开发工作流调研.md` 的"根指令文件当目录用"和"一份覆盖更新的状态文件"两节。
